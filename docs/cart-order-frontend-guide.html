장바구니 · 주문 연동 가이드

장바구니와 주문서(결제하기 직전까지)가 서버에 올라갔습니다. 기존 엔드포인트는 하나도 바꾸지 않았습니다 — 상품상세만 /product/v1/:id 를 새로 만들었고 구버전은 그대로 둔 채 deprecated 표시만 했습니다.

결제(LINE Pay · ECPay) 연동과 결제 콜백은 다음 스코프입니다. 지금은 주문을 PENDING 으로 만드는 것까지입니다.

01

먼저 알아야 할 것

상품상세를 v1 으로 옮겨야 담기가 됩니다

기존 GET /product/:id 의 option 은 "색 2개, 사이즈 2개" 같은 축별 목록이라 어떤 조합이 실제로 존재하는지, 그 조합의 재고와 variantId 가 무엇인지 알 수 없습니다. 장바구니 담기는 재고 단위인 productVariantId 를 받으므로 구버전 응답만으로는 담을 수가 없습니다.

GET /product/v1/:id 는 variants 배열을 추가로 내려줍니다. 기존 option 맵도 그대로 함께 오므로 화면을 한 번에 다 고칠 필요는 없습니다.

v1 에서 달라지는 것은 두 가지뿐

  • variants 추가 — 옵션 조합별 id(=productVariantId) · sku · optionValueIds · stockQuantity · isSoldOut
  • shippingCost 제거 — 배송비가 상품이 아니라 배송지로 정해지도록 바뀌었습니다. 상품별 배송비를 그대로 보여주면 주문서 금액과 어긋납니다. 안내가 필요하면 GET /shipping-policy 를 쓰세요. shippingInfo(출고 소요일)는 그대로 있습니다.

공통 규약

  • 인증 — Authorization: Bearer <oneTimeToken>. 로그인 응답의 data.token 입니다. 장바구니·주문은 전부 로그인 필수입니다.
  • 비로그인 — 서버는 게스트 장바구니를 지원하지 않습니다. 로컬스토리지에 담아뒀다가 로그인 직후 POST /user/cart 를 순서대로 호출해 밀어 넣으세요.
  • 언어 — Accept-language: ko | en | zh-TW. 장바구니 조회 · 주문 미리보기 · 주문 생성 · 상품상세 v1 에 필요합니다.
  • 응답 봉투 — 단건은 { result, data }, 목록은 { result, data: { total, list } }. 아래 예시는 data 안쪽만 적었습니다.
  • 금액 단위 — 전부 정수 TWD 입니다. 소수점이 없습니다.
02

화면 흐름

각 단계에서 부를 API
01 상품상세 옵션 조합을 variants 로 매칭해 variantId 를 확보하고, 품절 조합은 비활성화합니다. GET /product/v1/:id POST /user/cart
02 /cart 브랜드별로 묶어 보여줍니다. 배송비는 배송지를 모르니 본섬 기준 예상값입니다. GET /user/cart PATCH · DELETE /user/cart
03 /order 선택한 라인만 넘깁니다. 주소를 바꿀 때마다 preview 를 다시 불러 금액을 갱신합니다. POST /user/order/preview POST /user/order
04 /order/complete 주문번호·결제수단·배송지를 보여줍니다. 결제 연동은 다음 스코프입니다. GET /user/order/:id

하지 말아야 할 것

  • 주문 생성 후 장바구니를 지우지 마세요. 서버도 안 비웁니다. 결제창에서 이탈하면 담아둔 것이 사라져야 할 이유가 없습니다. 비우는 시점은 결제 성공 이후이고, 그건 다음 스코프에서 서버가 처리합니다.
  • 품절 라인을 자동으로 삭제하지 마세요. isAvailable: false 로 내려오면 흐리게 표시하고 사용자가 직접 지우게 합니다.
  • 장바구니의 배송비를 확정 금액처럼 보여주지 마세요. 필드 이름에 estimated 가 붙은 이유입니다. 주문서에서 금액이 바뀌면 사용자는 오류로 받아들입니다.
  • 선택(체크박스) 상태를 서버에 저장하려 하지 마세요. 저장 API가 없습니다. 화면 상태로 들고 있다가 주문 시 cartItemIds 로 넘기면 됩니다.
03

배송비 규칙

이 문서에서 가장 헷갈리는 부분

배송비는 상품이나 브랜드가 아니라 배송지 지역으로 정해지고, 주문 1건당 한 번만 붙습니다. 브랜드를 몇 개 담든 배송비는 1건입니다. 그래서 목업에 있던 브랜드 그룹별 배송비 표기와 결제금액 패널의 배송비 내역 하위 행은 실제와 다릅니다 — 걷어내야 합니다.

순서규칙결과
1 상품 금액 합이 freeShippingThreshold 이상 (경계 포함) 배송비 0 — 외섬이라도 0입니다
2 미만이고 배송지가 외섬이며 프로모션 중이 아님 remoteIslandFee
3 그 외 (본섬, 또는 외섬 프로모션 중) baseFee

외섬 판정은 서버가 합니다

프론트가 지역 목록을 들고 있을 필요가 없습니다. city 와 district 를 preview 에 넘기면 서버가 판정해 isRemoteIsland 와 확정 배송비를 돌려줍니다. 판정 대상은 澎湖縣 · 金門縣 · 連江縣(馬祖) 전체와 臺東縣의 綠島鄉 · 蘭嶼鄉 입니다 — 같은 臺東縣이라도 臺東市는 본섬입니다.

臺 / 台 표기가 갈려도 서버가 정규화해서 판정합니다. 그래도 가능하면 한 표기로 통일해서 보내주세요.

현재 요율 (2026-09-04)

값은 관리자 화면에서 바뀔 수 있으니 화면에 하드코딩하지 말고 GET /shipping-policy 로 받아 쓰세요.

  • baseFee NT$60 · remoteIslandFee NT$100
  • remoteIslandPromotion true — 현재 프로모션 중이라 외섬도 NT$60 이 적용됩니다
  • freeShippingThreshold NT$1,150 — 테스트값(약 5만원)이라 오픈 전 조정될 수 있습니다
GET /shipping-policy 인증 불필요

배송비 안내 문구를 프론트에 하드코딩하지 않기 위한 조회입니다.

Response 200 
{
  "baseFee": 60,
  "remoteIslandFee": 100,
  "remoteIslandPromotion": true,
  "freeShippingThreshold": 1150
}
04

상품상세 v1

GET /product/v1/:id 선택적 인증

Accept-language 필요. 토큰을 보내면 isLiked 가 채워집니다. :id 는 숫자만 받습니다.

Response 200 — 변경분만 
{
  // ... 기존 v0 필드 그대로 (name, brand, price, discountPrice,
  //     origin, shippingInfo, option, like, review, detailImg,
  //     subImage, relate, external, isLiked)
  // shippingCost 는 없습니다

  "variants": [
    {
      "id": 101,                        // ← POST /user/cart 의 productVariantId
      "sku": "ONDO-IVORY-M",
      "optionValueIds": [1, 5],         // option 맵의 값 id 조합
      "stockQuantity": 5,
      "isSoldOut": false
    },
    {
      "id": 102,
      "sku": "ONDO-IVORY-L",
      "optionValueIds": [1, 6],
      "stockQuantity": 0,
      "isSoldOut": true
    }
  ]
}

쓰는 법 — 사용자가 고른 옵션값 id 들을 정렬해 optionValueIds 와 일치하는 variant 를 찾습니다. 일치하는 게 없으면 존재하지 않는 조합이니 선택을 막고, 찾았는데 isSoldOut 이면 품절로 표시합니다. 서버 호출 없이 로컬에서 판단됩니다.

05

장바구니

전부 로그인 필수
POST /user/cart Bearer

단건·다건이 같은 API 입니다. 상품상세에서 옵션 조합을 여러 개 골라 한 번에 담는 화면이 있어 items 는 항상 배열입니다 — 한 개만 담을 때도 길이 1 배열로 보냅니다. 이미 담긴 SKU 면 라인이 늘지 않고 수량이 더해집니다. 헤더 뱃지를 바로 갱신할 수 있도록 담은 뒤의 총 라인 수를 함께 돌려줍니다.

Request 
{
  "items": [                     // 1 ~ 50 건
    { "productVariantId": 101, "quantity": 2 },  // quantity 1 ~ 999
    { "productVariantId": 102, "quantity": 1 }
  ]
}
Response 201 
{
  "items": [                     // 요청 순서 그대로
    { "productVariantId": 101, "cartItemId": 12, "quantity": 5 },
    { "productVariantId": 102, "cartItemId": 13, "quantity": 1 }
  ],
  "totalCount": 3   // 라인 수 (수량 합 아님)
}

응답의 quantity 는 이미 담겨 있던 수량이 더해진 최종 값입니다. 한 요청에 같은 SKU 가 두 번 들어오면 서버가 합쳐서 한 라인으로 담습니다.

하나라도 담을 수 없으면 전부 담기지 않습니다. 절반만 담기면 선택 패널이 어떤 상태여야 하는지 애매해지기 때문입니다. 재고 부족이면 409, 없는 SKU 면 404 이고, 어느 것이 문제인지 data 에 실려 옵니다 — 해당 줄에 바로 표시하면 됩니다.

// 409
{ "message": "Not enough stock. productVariantId: 102, available: 1, requested: 2",
  "code": "CONFLICT",
  "data": { "productVariantId": 102, "available": 1, "requested": 2 } }

// 404
{ "code": "NOT_FOUND_DATA",
  "data": { "productVariantIds": [999999] } }

재고는 누적 수량 기준입니다. 이미 2개 담긴 상태에서 재고가 3인데 2개를 더 담으면 409 입니다.

GET /user/cart Bearer

Accept-language 필요. 브랜드 그룹은 표시용이고 배송비는 그룹과 무관합니다.

Response 200 
{
  "brandGroups": [
    {
      "brandId": 1,
      "brandName": "온도",
      "brandProfileImage": "https://...",
      "productAmount": 2560,        // 구매 가능 라인만 합산
      "items": [
        {
          "cartItemId": 12,
          "productItemId": 10,
          "productVariantId": 101,
          "productName": "코튼 트윌 오버셔츠",
          "optionText": "IVORY / M",
          "imageUrl": "https://...",
          "price": 1400,             // 정가
          "discountPrice": 1280,     // 없으면 0
          "quantity": 2,
          "totalPrice": 2560,        // 적용가 × 수량
          "stockQuantity": 5,
          "isSoldOut": false,
          "isAvailable": true        // false 면 금액에서 제외됨
        }
      ]
    }
  ],
  "totalProductAmount": 2560,
  "estimatedShippingFee": 60,      // 본섬 기준 예상값
  "remoteIslandFee": 100,          // 안내 문구용
  "freeShippingThreshold": 1150,
  "amountToFreeShipping": 0,        // "N원 더 담으면 무료배송"
  "estimatedTotalAmount": 2620,
  "totalCount": 3
}

금액 합계는 isAvailable: true 인 라인만 더합니다. 살 수 없는 것을 합계에 넣으면 무료배송까지 남은 금액이 틀리기 때문입니다. 라인은 지우지 않고 그대로 내려줍니다.

GET /user/cart/count Bearer

헤더 뱃지 전용입니다. 응답은 { "count": 3 } — 수량 합이 아니라 라인 수입니다.

PATCH /user/cart/:id Bearer

수량 변경. Body { "quantity": 4 }. 성공 시 204 · 본문 없음. 재고를 넘기면 409, 남의 라인이면 404 입니다.

DELETE /user/cart/:id Bearer

라인 1건 삭제. 204 · 본문 없음. 지운 뒤 같은 SKU 를 다시 담을 수 있습니다.

DELETE /user/cart?ids=1,2,3 Bearer

선택 삭제. ids 를 생략하면 전체를 비웁니다 — 실수로 빼먹지 않게 주의하세요. ids=1,2,3 와 ids=1&ids=2 둘 다 받습니다. 최대 100건. 204 · 본문 없음.

06

주문

POST /user/order/preview Bearer

DB 를 건드리지 않습니다. 주문서 진입 시 한 번, 그리고 주소(縣市·區)를 바꿀 때마다 다시 부르세요. 배송비가 주소로 정해지기 때문입니다. Accept-language 필요.

주문 라인을 넘기는 방법이 둘입니다. 둘 중 정확히 하나만 보내세요 (같이 보내거나 둘 다 빼면 400).

  • cartItemIds — 장바구니에서 선택한 라인으로 주문할 때
  • items — 상품상세 "구매하기". 장바구니를 거치지 않습니다. 담기 API 로 우회하지 마세요 — 담기는 이미 담긴 수량과 합산되어 주문 수량이 틀어집니다.
Request — 장바구니에서 주문 
{
  "cartItemIds": [12, 13],  // 1 ~ 100건
  "city": "臺北市",
  "district": "信義區"
}
Request — 상품상세 "구매하기" 
{
  "items": [
    { "productVariantId": 101, "quantity": 2 }
  ],
  // city·district 를 빼면 본섬 기준 예상 배송비가 옵니다
  "city": "臺北市",
  "district": "信義區"
}
Response 200 
{
  "brandGroups": [ /* GET /user/cart 와 동일 */ ],
  "totalProductAmount": 900,
  "shippingFee": 60,
  "isRemoteIsland": false,
  "isShippingEstimated": false,  // true 면 본섬 기준 예상값
  "freeShippingThreshold": 1150,
  "amountToFreeShipping": 250,
  "totalAmount": 960
}

존재하지 않거나 남의 cartItemIds 가 하나라도 섞이면 404, items 의 productVariantId 가 없어도 404 입니다.

items 로 부르면 brandGroups[].items[].cartItemId 는 null 입니다 — 장바구니 라인이 아니기 때문입니다. 수량 변경 UI 를 이 값으로 그리고 있다면 주의하세요.

주소를 아직 등록하지 않은 회원은 city·district 를 빼고 부르면 됩니다. isShippingEstimated: true 로 본섬 기준 예상 배송비가 내려오니, 화면에는 "예상 배송비"로 표시하고 주소를 고른 뒤 다시 부르세요.

POST /user/order Bearer

결제하기 버튼에 연결합니다. 주문이 PENDING 으로 생성됩니다. 재고는 차감되지 않고 장바구니도 비워지지 않습니다. Accept-language 필요.

Request — 기본 배송지 사용 
{
  // preview 와 같이 cartItemIds 또는 items 중 하나
  "cartItemIds": [12, 13],
  "paymentMethod": "LINE_PAY",  // 또는 "ECPAY"
  "useDefaultShipping": true
}
Request — 직접 입력 + "구매하기" 
{
  "items": [
    { "productVariantId": 101, "quantity": 1 }
  ],
  "paymentMethod": "ECPAY",
  "useDefaultShipping": false,
  "shipping": {
    "recipientName": "李佳蓉",
    "phone": "+886912345678",
    "postalCode": "110",
    "city": "臺北市",
    "district": "信義區",
    "detailAddress": "松高路 11號 5樓",
    "requestMessage": "부재 시 경비실"  // 선택
  }
}
Response 201 
{
  "orderId": 481,
  "orderNumber": "SM-20260903-000481",
  "totalAmount": 960
}

items 로 만든 주문은 장바구니를 전혀 건드리지 않습니다 — 담기지도, 비워지지도 않습니다. 재고가 모자라면 409 이고 주문은 만들어지지 않습니다.

useDefaultShipping: true 면 서버가 GET /user/profile(주소)과 GET /user/info(전화번호)에 해당하는 값을 읽어 씁니다. 하나라도 비어 있으면 400 이니, 주문서에서 미리 채워졌는지 확인하고 비면 프로필 입력으로 유도하세요. 기본 배송지 조회 전용 API 는 따로 만들지 않았습니다 — 기존 두 API 를 조합하면 됩니다.

GET /user/order/:id Bearer

에러

08

어드민

운영 화면이 필요하면

배송비 요율과 외섬 지역을 관리자 화면에서 바꿀 수 있습니다. 전부 Authorization: Bearer <admin oneTimeToken> 이 필요합니다. 이미 만들어진 주문의 금액은 스냅샷이라 여기서 요율을 바꿔도 변하지 않습니다.
