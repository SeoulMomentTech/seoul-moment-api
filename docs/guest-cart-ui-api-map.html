게스트 장바구니

왼쪽은 실제로 붙을 화면, 오른쪽은 그 화면의 각 요소가 부르는 API다. 번호가 좌우를 잇는다 — 어느 쪽이든 올려두면 짝이 같이 켜진다.

로그인 없이 담기 · 보기 결제 없음 심사 후 삭제 2026-09-21

심사용 임시

심사가 끝나면 이 API 6개는 통째로 지운다. 회원 장바구니(/user/cart)를 대체하지 않는다. DB 테이블을 쓰지 않아 지울 때 마이그레이션도 없다.

인증

토큰이 필요 없다. 장바구니는 x-guest-id 헤더의 게스트 ID 로만 구분한다.

응답 봉투

성공은 { result, data }. 이 문서의 → 는 data 안쪽만 적었다. 실패는 { message, code, traceId, data? }.

금액

통화는 NT$, 전부 정수다. 배송지를 모르므로 배송비는 본섬 기준 예상값이다.

필드 표기

key 필수 · key? 선택(응답에선 null 가능). 정의하지 않은 키를 보내면 400 이다.

변경 표기

new 이번 심사용으로 새로 만든 API. 라벨이 없는 카드(상품·배송비 정책)는 기존 그대로다.

사용된 API

1주문하기
API 없음화면 이동만

게스트 주문 API 는 없다. /user/order/preview·/user/order 는 전부 회원 토큰을 요구한다. 누르면 로그인 화면으로 보내고, 로그인 뒤에는 회원 장바구니에 다시 담아야 한다.

심사 범위 밖
2로그인 유도
기존 로그인 화면/user/auth/*

기존 로그인 흐름을 그대로 쓴다. 게스트 장바구니는 로그인해도 남아 있고 옮겨지지 않는다 — "담긴 것이 사라졌다" 는 문의가 나오지 않게 안내 문구를 넣어두는 편이 낫다.

심사가 끝나면 이 문서의 /guest/cart 6개와 서버 모듈을 함께 지운다. 화면도 회원 장바구니 하나로 돌아간다.

호출 순서 한 장

상품을 보고 담아서 장바구니를 확인하는 데까지. 실제로 나가는 요청만 순서대로.

01

상품상세 진입

토큰 없이 그대로 된다. 정책은 캐시해 두면 다음 상품에서 생략할 수 있다.

GET /product/v1/:id GET /shipping-policy
02

옵션 선택

호출 없음. 응답의 variants 에서 조합을 찾아 productVariantId 를 확정한다.

03

담기 — 첫 호출만 헤더 없이

응답의 guestId 를 저장한다. 이후 모든 게스트 요청에 x-guest-id 로 실어 보낸다.

POST /guest/cart
04

장바구니 진입

목록과 금액이 이 응답 하나에서 나온다. 뱃지는 담기 응답의 totalCount 로 이미 갱신돼 있다.

GET /guest/cart
05

수량 변경 · 삭제

둘 다 204 라 금액을 다시 받으려면 조회를 한 번 더 부른다. 키는 productVariantId 다.

PATCH /guest/cart/:productVariantId DELETE /guest/cart/:productVariantId GET /guest/cart
06

주문하기

호출 없음. 로그인 화면으로 보낸다. 게스트 주문·결제는 만들지 않았다.

전체 필드·에러는 Swagger https://api-dev.seoulmoment.com.tw/docs 의 GuestCart 태그에서 본다. 서버 모듈은 apps/api/src/module/guest/cart/ 한 폴더에 모여 있고, 통합 테스트는 test/guest.cart.spec.ts 다. 심사가 끝나면 폴더와 api.module.ts·main.ts 의 참조 두 줄을 지우면 된다.
