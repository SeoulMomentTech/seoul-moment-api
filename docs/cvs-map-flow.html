① 편의점 고르기는 이렇게 돌아요

fetch로 부르는 API가 아니에요. 브라우저가 다른 사이트에 다녀오는 거예요. 결제창이랑 같은 방식이에요.

🖥️ 우리 프론트 (주문서)
⚙️ 우리 서버
🗺️ ECPay 편의점 지도
1"편의점 고르기" 버튼 클릭
→ 입력값 저장해 두고
location.href = /logistics/cvs/map?chain=UNIMART&returnUrl=주문서주소
↓ 브라우저가 우리 서버로 이동
2returnUrl을 기억해 두고
ECPay 지도로 브라우저를 넘겨요
↓ 브라우저가 ECPay로 이동
3사용자가 지도에서 매장을 골라요
(테스트 환경은 지도 없이 고정 매장이 바로 골라져요)
↓ 고른 매장을 들고 우리 서버로
4매장을 1시간 보관하고 토큰을 만들어요
→ returnUrl?cvsStoreToken=abc123 으로 돌려보내요
↓ 브라우저가 주문서로 돌아옴
5주소창의 토큰으로
GET /logistics/cvs/store/abc123
→ 매장명·주소를 화면에 보여줘요
↓
6주문 만들 때
cvsPickup.storeToken: "abc123"
💡 한 줄 요약: 보내고 → 고르고 → 토큰 들고 돌아온다. 페이지를 떠났다 오니까 주문서 입력값은 미리 저장해 두세요.

② returnUrl은 왜 안 먹혀요? (localhost)

4번에서 서버가 아무 주소로나 돌려보내면 피싱에 쓰일 수 있어서, 등록된 프론트 주소만 통과시켜요.

https://등록된프론트/checkout
🚧 서버 검문소
STOREFRONT_BASE_URL로
시작하나?
✅ 통과 → 주문서로 돌아감
?cvsStoreToken=abc123
http://localhost:3000/checkout
(아직 등록 안 됨)
❌ 무시 → 서버 화면에
"已選擇門市 … token=abc123" 이 떠요
💡 localhost 자체는 문제없어요. 돌아가는 건 내 브라우저라서 서버가 localhost에 접속할 일이 없거든요. 등록만 안 돼 있는 것뿐이에요.
지금 당장 테스트하려면: returnUrl 없이 열기 → 마지막 화면의 token= 값 복사 → localhost:3000/checkout?cvsStoreToken=복사한값 으로 직접 들어가기
