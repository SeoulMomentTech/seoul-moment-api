왼쪽은 실제로 붙을 화면, 오른쪽은 그 화면의 각 요소가 부르는 API다. 번호가 좌우를 잇는다 — 어느 쪽이든 올려두면 짝이 같이 켜진다.

커밋 6e6ac66 국제배송비 지원 할인 배송 6단계 · 24시간 발주 타이머 DEV 배포 전 — 실측은 배포 후

인증

고객 API는 회원 Authorization: Bearer. 관리자 API(/admin/*)는 관리자 토큰이다 — 회원 토큰으로 부르면 401.

응답 봉투

단건은 { result, data }, 목록은 { result, data: { total, list } }. 이 문서의 → 는 data 안쪽만 적었다. 204 는 본문이 없다.

상태 문구 · 언어

상태는 코드(deliveryStage)로 분기하고 화면에는 서버가 준 …Label 을 그대로 쓴다. 헤더 Accept-Language: ko | en | zh-TW. 비우거나 모르는 값이면 한국어.

금액

통화는 NT$, 전부 정수. 합계(totalAmount)는 이미 할인이 빠진 값이라 프론트가 다시 빼지 않는다.

필드 표기

key 필수 · key? 선택(응답에선 null 가능) · key* 조건부 필수(조건은 카드 본문) · // ① // ② 택1. 정의하지 않은 키를 보내면 400 이다(전역 forbidNonWhitelisted).

변경 표기

기준은 payment-ui-api-map.html(결제 1차, 2026-11-04). new 새 API · updated 필드가 늘어난 API. 라벨이 없으면 예전 그대로다.

Swagger

DEV api-dev.seoulmoment.com.tw/docs · PROD api.seoulmoment.com.tw/docs. 배포 전이라 링크는 DEV 배포 뒤에 열린다 (PROD 는 main 뒤).

실측

예시 값은 코드와 테스트(42건)에서 가져왔다. DEV 배포 후 실측 예정 — 실측하면 이 카드를 갱신한다.

주의 — “24시간 경과 = 발주 가능”은 회사 내부 발주 기준이지 고객의 취소·계약해제 권리가 끝났다는 뜻이 아니다. 이 화면에서 취소 신청 경로를 막지 않는다. 또 기존 결제 완료 주문은 전부 “발주 가능”으로 보인다(과거 주문 백필 전) — DEV 는 테스트 데이터라 괜찮지만 PROD 전에 정리가 필요하다.
